# 使用说明

## 初始化环境

```bash
cd /home/ubuntu/gcj/projects/data_collect/data_processed
UV_CACHE_DIR=/tmp/piper-data-process-uv-cache uv sync --group dev
```

## 项目 FFmpeg

系统 `ffmpeg` 在本机因动态库冲突无法启动。项目不调用该二进制，而是固定使用 `imageio-ffmpeg==0.6.0` 随 `uv` 环境安装的静态 FFmpeg。

```bash
UV_CACHE_DIR=/tmp/piper-data-process-uv-cache uv run piper-project-ffmpeg --check
```

该命令会输出可执行文件路径和版本，并验证 `libx264` 编码器。无需修改 `PATH`。

## 转换数据

转换由 [corn_in_plate.yaml](../configs/corn_in_plate.yaml) 控制。两种模式都会生成 LeRobot 格式；当前机器只有图片模式可直接用于 OpenPI 训练：

| `output.use_videos` | LeRobot 特征类型 | 输出位置 | 适用场景 |
| --- | --- | --- | --- |
| `true` | `video` | `videos/chunk-*/image/*.mp4`、`videos/chunk-*/wrist_image/*.mp4` | 文件数少，适合归档、传输和已修复视频解码环境的训练 |
| `false` | `image` | 图像二进制嵌入 `data/chunk-*/*.parquet` | 当前机器推荐；可直接供 OpenPI/LeRobot 读取，不依赖系统动态 FFmpeg |

默认配置启用图片模式：

```bash
UV_CACHE_DIR=/tmp/piper-data-process-uv-cache \
uv run piper-hdf5-to-lerobot --config configs/corn_in_plate.yaml --quiet
```

需要重建已有数据集时，显式传入 `--overwrite`。转换先写入暂存目录，全部成功后才替换目标数据集。

```bash
UV_CACHE_DIR=/tmp/piper-data-process-uv-cache \
uv run piper-hdf5-to-lerobot --config configs/corn_in_plate.yaml --overwrite --quiet
```

需要 MP4 模式时，将配置改为：

```yaml
output:
  use_videos: true
```

建议同时使用不同 `output.root` 和 `output.repo_id`，避免覆盖已有图片数据集。图片模式不会生成 MP4 或 `videos/`；这是预期行为。

MP4 位于 `datasets/taiyigong333/piper_corn_in_plate/videos/`。默认使用 `libx264`、`CRF 23`、30 帧关键帧间隔；这些值可在 `output` 配置段修改。`video_preset` 越慢通常文件越小但转换越慢，`video_crf` 越小画质越高且文件越大。

当前机器的 LeRobot 标准视频解码不可用：`torchcodec` 会链接损坏的系统动态 FFmpeg，PyAV 回退需要的 `torchvision.io.VideoReader` 也不可用。因此 MP4 转换已验证可用，但当前机器上使用 OpenPI 训练必须保持 `use_videos: false`，直到修复系统动态 FFmpeg 或升级为可用的视频解码环境。

## 转换后验证

视频模式可检查 MP4 数量；双相机数据集的预期数量为轨迹数的两倍：

```bash
find datasets/taiyigong333/piper_corn_in_plate/videos -name '*.mp4' | wc -l
```

当前图片模式可由 LeRobot 直接读取：

```bash
HF_HOME=/tmp/piper-data-process-hf \
HF_LEROBOT_HOME=/home/ubuntu/gcj/projects/data_collect/data_processed/datasets \

```

## 使用本地数据集训练 OpenPI

本节使用项目内已转换的数据集 `taiyigong333/piper_corn_in_plate` 微调 OpenPI。保持 `configs/corn_in_plate.yaml` 中的 `output.use_videos: false`：当前机器的图片 Parquet 数据可直接训练，MP4 数据受系统动态 FFmpeg 解码问题影响，不能直接用于训练。

当前数据集有 100 条轨迹、20,310 帧，字段为两路 224 x 224 RGB 图像、7 维 `state`、7 维 `actions` 和任务文本 `pick up the corn and put it on the plate`。`state` 与 `actions` 的前六维是 Piper 关节角，最后一维是夹爪开度。

### 训练前准备

OpenPI 使用独立的 `uv` 环境，不复用本项目根目录的 `.venv`。需要 Ubuntu 和 NVIDIA GPU；OpenPI 当前版本估计 LoRA 微调至少需要 22.5 GB 显存，完整微调至少需要 70 GB 显存。

```bash
cd /home/ubuntu/gcj/projects/data_collect/data_processed/openpi
export UV_CACHE_DIR=/tmp/openpi-uv-cache
export HF_LEROBOT_HOME=/home/ubuntu/gcj/projects/data_collect/data_processed/datasets
export OPENPI_DATA_HOME=/home/ubuntu/gcj/projects/data_collect/data_processed/openpi-cache
GIT_LFS_SKIP_SMUDGE=1 uv sync
GIT_LFS_SKIP_SMUDGE=1 uv pip install -e .
nvidia-smi
uv run python -c "import jax; print(jax.devices())"
```

`HF_LEROBOT_HOME` 必须指向 `datasets` 的上一层，因此 OpenPI 会在 `datasets/taiyigong333/piper_corn_in_plate` 找到本地数据，而不会从 Hugging Face 下载。`OPENPI_DATA_HOME` 用于缓存自动下载的基础模型权重。

可先确认 OpenPI 环境能读取数据集：

```bash
uv run python -c "from lerobot.common.datasets.lerobot_dataset import LeRobotDataset; dataset = LeRobotDataset('taiyigong333/piper_corn_in_plate'); print(len(dataset), dataset[0]['state'].shape, dataset[0]['actions'].shape)"
```

预期输出的样本数为 `20310`，两个向量的最后一维均为 `7`（不同 PyTorch/LeRobot 版本可能显示为 `torch.Size([7])` 或 `(7,)`）。

### 注册 Piper 训练配置

OpenPI 的训练和归一化统计命令都通过配置名工作，不能只在命令行中替换数据集名称。因此在固定子模块 `openpi/src/openpi/training/config.py` 的 `_CONFIGS = [` 列表末尾、闭合 `]` 之前加入以下配置。该配置复用 OpenPI 已提供的 LeRobot/LIBERO 字段映射：本项目的 `image`、`wrist_image`、`state`、`actions` 恰好与其输入契约一致。

```python
    TrainConfig(
        name="pi0_fast_piper_corn_lora",
        model=pi0_fast.Pi0FASTConfig(
            action_dim=7,
            action_horizon=10,
            max_token_len=180,
            paligemma_variant="gemma_2b_lora",
        ),
        data=LeRobotLiberoDataConfig(
            repo_id="taiyigong333/piper_corn_in_plate",
            base_config=DataConfig(prompt_from_task=True),
            extra_delta_transform=True,
        ),
        weight_loader=weight_loaders.CheckpointWeightLoader(
            "gs://openpi-assets/checkpoints/pi0_fast_base/params"
        ),
        freeze_filter=pi0_fast.Pi0FASTConfig(
            action_dim=7,
            action_horizon=10,
            max_token_len=180,
            paligemma_variant="gemma_2b_lora",
        ).get_freeze_filter(),
        ema_decay=None,
        batch_size=8,
        num_train_steps=30_000,
        save_interval=1_000,
        wandb_enabled=False,
    ),
```

保存后可确认配置已被 OpenPI 注册：

```bash
uv run python -c "from openpi.training import config; train_config = config.get_config('pi0_fast_piper_corn_lora'); print(train_config.data.repo_id, train_config.model.action_dim, train_config.model.action_horizon)"
```

预期依次输出数据集名称、动作维度 `7` 和动作块长度 `10`。

这是 π₀-FAST 的 LoRA 微调配置，适合单臂 7 自由度数据；`batch_size=8` 面向单张 24 GB 级别显卡。显存不足时将其减小为 `4` 或 `2`；多 GPU 时批大小必须可被 GPU 数量整除。显存充足并希望全量微调时，可参考同一文件中的 `pi0_fast_libero`：去掉 `paligemma_variant`、`freeze_filter` 和 `ema_decay=None`，但需要至少 70 GB 显存。

`extra_delta_transform=True` 只把前六维绝对关节目标变为相对当前关节位置的差值；夹爪仍保持绝对开度。策略推理输出会自动还原为绝对关节目标。该变换只适用于当前默认的六关节配置，详细依据见 [2026-07-24_OpenPI绝对动作训练变换核查.md](2026-07-24_OpenPI绝对动作训练变换核查.md)。

### 生成统计量并训练

仍在 `openpi` 目录，并保持上述三个环境变量。首先计算当前 Piper 数据的归一化统计量；此命令会写入 `openpi/assets/pi0_fast_piper_corn_lora/taiyigong333/piper_corn_in_plate/`。每次更换数据集、动作语义或训练配置后都要重新执行。

```bash
uv run scripts/compute_norm_stats.py --config-name pi0_fast_piper_corn_lora
```

统计量成功生成后启动训练。首次运行会自动下载 π₀-FAST 基础权重到 `OPENPI_DATA_HOME`，因此需要可访问 `gs://openpi-assets` 的网络。

```bash
XLA_PYTHON_CLIENT_MEM_FRACTION=0.85 \
uv run scripts/train.py pi0_fast_piper_corn_lora --exp-name=corn_v1 --overwrite
```

检查点会写入 `openpi/checkpoints/pi0_fast_piper_corn_lora/corn_v1/`。若训练中断，删除 `--overwrite` 并用相同实验名恢复：

```bash
XLA_PYTHON_CLIENT_MEM_FRACTION=0.85 \
uv run scripts/train.py pi0_fast_piper_corn_lora --exp-name=corn_v1 --resume
```

### 推理接入约束

可用训练完成的检查点启动策略服务；将 `<checkpoint_step>` 替换为检查点目录中的实际步数。

```bash
uv run scripts/serve_policy.py policy:checkpoint \
    --policy.config=pi0_fast_piper_corn_lora \
    --policy.dir=checkpoints/pi0_fast_piper_corn_lora/corn_v1/<checkpoint_step>
```

Piper 控制端向该策略提供的观测必须保持训练时的物理语义和键名：`observation/image`、`observation/wrist_image` 为 HWC、`uint8` 的 RGB 图像；`observation/state` 为 `[J1, J2, J3, J4, J5, J6, gripper]` 的 `float32` 向量；`prompt` 使用训练任务文本。返回的 `actions` 是同一顺序的 7 维绝对关节目标和绝对夹爪开度。首次接入实体机器人前，应在限速、限位和急停有效的条件下验证关节顺序、角度单位与夹爪单位，不能直接把未经验证的策略输出下发给机器人。

## 常见问题

### `uv` 无法写入默认缓存

本机默认 `~/.cache/uv` 在受限环境中可能不可写。所有命令前设置 `UV_CACHE_DIR=/tmp/piper-data-process-uv-cache` 即可。

### 系统 `ffmpeg -version` 报动态库错误

这不会影响项目内静态 FFmpeg 的 MP4 编码，但会影响当前 LeRobot 的视频解码。不要通过修改 `PATH` 绕过它；使用 `uv run piper-project-ffmpeg --check` 验证项目内静态编码器即可。

### 想切换动作语义

默认文件保存绝对关节动作，便于检查、复用和推理还原。仅在不使用 OpenPI 的 `extra_delta_transform=True` 时，才建议将 `representation.action_representation` 改为 `relative`。

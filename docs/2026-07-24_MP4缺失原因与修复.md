# MP4 缺失原因与修复

## 原因

此前 `configs/corn_in_plate.yaml` 设置了 `output.use_videos: false`。在 LeRobot v2.1 中，这会将图像作为 `image` 特征嵌入每个 Parquet 文件，`meta/info.json` 的 `video_path` 为 `null`，因此不会创建 `videos/` 目录或 MP4 文件。

此外，当前 LeRobot 提交默认通过 PyAV 编码视频，并不会调用系统 `ffmpeg`。本机系统 `ffmpeg` 启动时存在 `libavfilter` 与 `libavutil` 符号不匹配，不能用于转换。

## 修复

默认配置保留 `output.use_videos: false`，以支持当前机器直接进行 OpenPI 训练。将其设为 `true` 后，转换器会使用 `uv` 安装的 `imageio-ffmpeg==0.6.0` 提供的静态 FFmpeg 7.0.2，编码参数为 `libx264`、`yuv420p`、`CRF 23`，生成可移植的 H.264 MP4。

编码入口在 `piper_data_process.ffmpeg`；转换时会替换固定 LeRobot 提交的 `encode_video_frames` 模块入口，因此不会通过 `PATH` 查找或调用损坏的系统 `ffmpeg`。

## 验证

```bash
UV_CACHE_DIR=/tmp/piper-data-process-uv-cache \
uv run piper-project-ffmpeg --check

find datasets/taiyigong333/piper_corn_in_plate/videos -name '*.mp4' | wc -l
```

双相机数据集应有 `轨迹数 × 2` 个 MP4 文件；本数据集为 100 条轨迹，因此预期为 200 个 MP4。

## 当前训练限制

MP4 编码已经通过真实轨迹验证，但该机器的 LeRobot 默认视频解码不可用：`torchcodec` 依赖系统动态 FFmpeg，共享库冲突；`pyav` 回退又依赖当前 `torchvision` 中缺失的 `VideoReader`。`imageio-ffmpeg` 提供的是静态编码器，不提供 `torchcodec` 所需的动态库。因此在当前机器用 OpenPI 训练时，请继续使用 `use_videos: false` 的图片模式。
